# Agent Note: 租户控制平面创建隔离的 Harness 实例

Status: implemented

[English](2026-08-14-tenant-control-plane.md) | 中文

## Problem

Harness 当前没有经过认证的账户、租户归属或角色模型。部署中的 `admin` 凭据只是在反向代理层保护一个共享实例，因此增加更多代理凭据后，所有操作者仍会看到相同的会话、工作区、设置和数据。

如果在 Harness 内部增加租户归属，部署管理就会与快速演进的会话、工作区、设置、凭据和客户端 API 耦合。当前部署需要在不修改这些产品领域的前提下提供用户隔离、服务器容量限制和管理员视图。

## Decision

DeepHarness 租户管理作为部署侧控制平面运行在 Harness 包图之外。一个租户对应一个受资源限制的 Harness 容器、一个主机端口和一个持久化 Docker 数据卷。控制平面使用开启 WAL 模式的 SQLite 保存实例期望状态和管理操作记录。

双方的集成面仅包括已发布的 Harness 镜像、`/data` 数据卷、Basic Auth 环境变量和 Docker 容器状态。Harness 的会话、工作区、凭据和插件持久化保持不变。

创建租户时会检查主机 CPU 采样值、一分钟负载、可用内存、磁盘剩余比例，以及活动租户 CPU 和内存配额总和。异常状态实例仍计入配额，因为管理员移除实例之前，相应 Docker 资源可能仍然存在。

控制平面使用独立管理员凭据，并要求所有变更 API 带防护请求头。租户密码只生成并返回一次，不写入 SQLite。控制平面变更现有容器之前会校验管理标签；创建操作只能使用已配置的资源上限、镜像、端口范围和生成名称。

移除租户时删除容器并默认保留数据卷，只有 API 调用方明确要求清理时才删除数据。操作日志保留执行结果和错误详情。SQLite 与各租户 Docker 数据卷是相互独立的备份单元。

## Alternatives considered

- **在 Harness 核心增加用户和租户归属**：未采用，因为会话、工作区、设置、凭据、API 和 WebSocket 路径都需要增加面向当前用户的鉴权和迁移。
- **为同一个 Harness 实例增加多个 Caddy Basic Auth 用户**：未采用，因为这样只能分开登录凭据，无法隔离数据、设置、权限或审计归属。
- **只生成 Compose 文件来记录租户**：未采用，因为生命周期状态、资源准入、运行态协调和操作历史需要可查询的持久化状态。
- **控制平面使用 PostgreSQL**：未采用，因为单控制器部署下，SQLite WAL 已能在不增加额外服务的情况下提供所需持久性和事务。

## Consequences

- 每个租户拥有独立运行状态、数据卷、凭据、资源限制和故障范围，同时复用同一个不可变 Harness 镜像。
- Harness 升级仍然只是镜像变更，不需要在 Harness 内部执行租户相关迁移。
- 使用 SQLite 时控制平面只能单实例运行，不支持横向启动多个控制平面副本。
- 挂载 Docker socket 等同于授予主机级容器控制能力，因此该服务必须作为受认证保护的管理组件；扩展到多主机之前应改为权限收窄的 Host Agent API。
- 标准库单元测试覆盖容量准入、SQLite 更新和生命周期编排；API 冒烟覆盖认证、健康检查、看板序列化和静态页面交付。
