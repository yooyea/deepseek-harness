# Agent Note: DeepHarness 品牌通过客户端覆盖插件实现

Status: implemented

[English](2026-08-14-deepharness-brand-plugin.md) | 中文

## Problem

当前部署需要展示 DeepHarness 产品身份，并隐藏上游内测声明和 DeepSeek 产品标识。如果直接修改上游设置、侧边栏、对话、基础组件和应用壳代码，会形成长期合并负担，也不符合仓库的插件所有权模型。

新手引导区域已经有稳定的插槽扩展点，但侧边栏和空状态尚未提供品牌专用插槽。因此部署需要一个可逆覆盖层：已有公开扩展点的地方使用插件注册，其他位置只针对精确的私有标记做 DOM 投影。

## Decision

部署品牌由独立浏览器插件 `@deepseek-ai/dsh-client-ui-brand-deepharness` 提供。上游设置、侧边栏、对话、基础组件和应用壳保持不变。

内测声明和官方模型提供方引导通过现有插槽注册表的优先级选举替换：覆盖插件以更低优先级注册相同稳定 id，并在不渲染内容的情况下完成该插槽。原插件继续保留以提供模型设置能力，同时不再展示首次运行产品内容。

侧边栏和空状态没有品牌专用插槽。覆盖插件只识别私有 DeepSeek 字标 clip id 和鱼形 SVG 的精确 view box，在其直接宿主上添加标记，再应用限定范围的 DeepHarness 字标或 DH 缩写。`MutationObserver` 会在 React 重新挂载后重复投影。同一个可逆副作用还负责文档标题、favicon 和 manifest 链接。

模型提供方名称、模型 id、包名和 API 命名空间保持不变，因为它们表示真实功能集成。

## Alternatives considered

- **直接修改上游 React 组件**：未采用，因为每次上游升级都会产生部署专属冲突，恢复上游品牌也需要还原源码。
- **对构建产物做大范围文字和 SVG 替换**：未采用，因为可能误改模型提供方配置、对话内容或其他图标。
- **等待上游为所有位置提供品牌插槽**：未采用，因为当前部署已经需要品牌能力；精确标记匹配使临时 DOM 投影保持狭窄且可替换。

## Consequences

- 删除覆盖插件配置即可恢复上游品牌和新手引导，无需回滚组件源码。
- 精确标记匹配避免大范围文本替换影响 DeepSeek 模型提供方配置或对话内容。
- 上游未来提供品牌插槽后，应使用该插槽替换 DOM 投影；新手引导覆盖仍可作为普通策略插件保留。
- 私有标记发生变化时可能暂时重新显示上游品牌，因此每次上游升级后仍需执行已部署浏览器冒烟检查。
